# Architecture

Lab 3 uses the same DocuAsk service shape as Lab 2, but the core failure is generated by a lab-local mock LLM instead of Toxiproxy. The mock can return deterministic alternating 503 responses so retry behavior is visible and repeatable.

```text
browser/curl
    |
    v
DocuAsk API :8080
    |
    +--> PostgreSQL/pgvector :5432
    +--> Redis :6379
    +--> mock-llm :8888

DocuAsk worker
    |
    +--> Redis
    +--> PostgreSQL/pgvector
    +--> mock-llm :8888
```

The API and worker both use:

```text
LLM_API_BASE=http://mock-llm:8888/v1
```

## Before

The before implementation has a bounded retry count, but it retries immediately when the LLM returns 429, 500, 502, 503, or 504. That keeps the code from looping forever, but it gives every caller the same retry timing. Under intermittent failures, aligned clients can create a retry storm and make a degraded dependency busier.

## After

The after implementation keeps the explicit attempt limit and retryable-status filtering, then adds exponential backoff, jitter, and explicit timeout budgets. The important behavior is not "retry forever"; it is "spend a visible retry budget, spread retry timing, and fail clearly when the budget is exhausted."

```text
attempt 1 -> immediate request
attempt 2 -> base delay + jitter
attempt 3 -> doubled delay + jitter
attempt 4 -> capped doubled delay + jitter
```
